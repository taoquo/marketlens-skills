Conclusion

示例标签为 event watch。日期确定、机制清楚，但有一道更硬的门槛：如果事件交付的正是价格已经隐含的东西，那它不是预期差，只是与市场一致。

36x @ r=8.5%、ROIC 40% 隐含永续增长 6.1%（r=9% 时 6.7%）。这已经把「服务业务持续双位数增长 + 硬件不失速」写进价格。所以 WWDC 若只交付渐进式平台升级，属于交付已隐含之物。

汇总读数 disciplined。因此本例中回购类公告的事件权重按记录折为常规项：兑现概率高但预期差低。如果同样规模的公告出自一家双口径 ROIIC 比值低于 0.9、回购金额不足 SBC 的公司，处理方式相反——公告规模再大也只记为 avoid only 的对冲行为，不进入每股价值。

三档事件定价规则

第一档，配置记录 disciplined：公告可按面值计入每股口径，但因为市场已经预期，预期差接近零，事件权重下调一档。第二档，记录 adequate：只计入已实际执行的部分，授权额度不计入，等待季度执行数据。第三档，记录 value-leaking 或 destructive：公告不进入估值，只作为管理层承诺兑现率的一次新样本。这条规则把「公告规模」与「公告价值」彻底分开。

本例的反向检验

假设 WWDC 后管理层宣布把年度回购提升到 FCF 的 110%，靠净增债务补足。按记录读数，这不会提高事件评分，反而触发两项复核：外部资金依赖从接近 0 升到正值，以及回购估值分位从 70th 推向 80th 以上。同一个公告在配置记录框架下是减分项，在只看公告规模的框架下会被读成利好。这就是本轮加入这一层的原因。

Red Flags

未取得 implied move、skew 或事件溢价时不能判断赔率。更重要的是：事件重要性不等于交易吸引力。当隐含预期已是 demanding，一个符合预期的发布会带来负向价格反应，这不是市场非理性，而是预期差为零。配置侧同理：把回购授权规模当成利好而不看公司自身的执行记录与回购时点估值分位，是本例第二个容易犯的错。

Decision Impact

日期确定支持 event watch；隐含预期 demanding 封住升级路径。只有出现价格未隐含的机制性变化且市场未充分定价，才升级 monitor closely；事件后若结果来自应计、资本化、一次性或税项，判定为 neutral 或 delayed 而不是 strengthened。资本配置类公告按上表三档折算后再进事件评分，不按公告金额排序。

What Would Change The View

升级条件：出现价格未隐含的量级证据（新收费层级、ARPU 机制、换机周期缩短可测），且能取得 implied move 以判断赔率。降级条件：发布内容已被充分预期、beta 反馈显示功能推迟、财报后的改善主要来自非运营来源，或回购提速伴随净增债务与更高的回购估值分位。
